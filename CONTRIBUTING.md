# Leave your changes here

[Home](README.md) · [中文](CONTRIBUTING.zh.md)

You do not need to join the organizing team or write a long introduction first. An unclear sentence, an outdated arrangement, or a question we missed is worth raising.

## You do not need Git to help

Open an [Issue](https://github.com/REFR-ACT/Hackathon-Playbook/issues) and tell us:

- Which page and passage are you reading?
- What is unclear, inaccurate, or likely to be difficult in practice?
- What would you change? A clear question helps even without an answer.

Do not attach student contact details, permission documents, financial records, or account information to a public discussion. Ask the organizers for an appropriate private route.

## If you want to edit a file

This repository uses Markdown only. There is no website build, image-asset step, or PDF upload requirement.

The home pages explain why the event exists and how to read the book. `docs/en/` and `docs/zh/` hold the English and Chinese chapters. The full organizing checklist lives in `operations.md`; future plans live in `roadmap.md`.

Keep a change focused and explain the reason in a pull request. Changes to dates, headcounts, qualification, judging, or funding should normally update both languages. If you can work in only one language, submit it and flag the other version for synchronization.

## The voice we want to keep

Be specific. Instead of saying we will “empower young creators,” explain what time, equipment, or help we intend to provide.

Do not invent memories of events that have not happened. Label examples as examples. Keep plans distinct from completed work and update approval status only when it changes. Source historical claims and identify design interpretations as interpretations. Do not invent partner schools, confirmed mentors, prize commitments, or a designer's experiences.

It is fine to care about the project and to admit what we do not yet know. Every paragraph does not need to be a manifesto.

## Before merging

- [ ] Relative links and contents entries work.
- [ ] Important numbers and status agree across languages.
- [ ] Factual claims have sources where needed; inference is not presented as fact.
- [ ] No personal information, credentials, internal approvals, or private conversations are published.
- [ ] No `output/`, previews, PDFs, or caches are mixed into the text changes.
- [ ] `git diff --check` passes.

## If you want to own a task

A short note is enough:

> What I want to help with:
> Time I can realistically contribute:
> What I can already do:
> Support I would need:
> When we could check progress:

Once someone accepts a task, record the owner and next step. A small piece of work completed is more useful than a page of promises nobody has taken on.
