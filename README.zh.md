# REFR/ACT Playbook

[English](README.md) · **中文**

> 动手之前，先让一个人的真实生活改变一下你的想法。

## 我们想从另一个问题开始

“我能做一个什么？”当然是个好问题。它让人兴奋，也很容易把大家带到编辑器和白板前面。

但我们总觉得，还少了前面那一步。

这是**谁**的问题？他真的需要一个新的 app 吗？如果没有稳定的网络，如果只能单手操作，如果根本没有时间学会我们精心设计的功能，这个看起来很完整的方案还成立吗？

我们对一些黑客松不太满足的地方就在这里：从点子到 demo 的速度越来越快，理解问题的时间却不一定跟着增加。两天过去，功能跑起来了，介绍也讲顺了，但最初想帮助的那个人，可能始终没有进入讨论。

REFR/ACT 想把顺序换一下。先理解，再让不同人的视角、需求和现实条件改变方案，然后动手。不是等到所有问题都有答案才开始，而是知道自己在验证什么，也愿意在证据不支持时换个方向。

这就是 Refract，折射。一个想法遇到真实世界之后，不必沿着最初的方向走到底。

## 我们还是高中生，想做的事也可以是真的

PRISMS 是一所 STEM 学校。科研训练教我们提出问题、找证据、检查自己的结论；我们想再多留出一种机会：把自己的想法做成别人可以试一试的东西。

不是把科研和创造分成两边。恰恰相反，严谨的提问可以让作品少一点想当然，亲手做东西也会暴露纸面上看不到的问题。

我们不想要求每个来的人都已经有一个很厉害的项目。可能你会写代码，可能你喜欢画图、拆东西、问问题，也可能你只是对学校里某件不方便的小事有点在意。这些都可以成为起点。

我们希望活动结束时，你带走的不只是演示文件，而是一次具体的经验：**我提出的想法，可以被认真讨论；我也有能力把它往前做一点。**

## 黑客松到底是什么

它是一次限时的、以团队项目为中心的创作活动。大家找问题、讨论方案、做原型、测试和修改，最后展示作品并回答问题。原型可以是一个 app、一件硬件、一个数据工具，也可以是让别人体验到核心想法的初步模型，不要求一天内做成完整产品。

会编程很有用，但不是唯一有用的能力。理解需求、设计交互、验证结果、解释取舍，都需要有人认真做。导师可以帮你排查问题，不会替你决定作品该成为什么。

在 REFR/ACT，每个团队选择一个主赛道，三个赛道分别设奖，但三种习惯应该出现在每个项目里：

- **Reflect：** 先弄清楚，我们看见的是谁的需要，哪些还只是猜测。
- **Refract：** 让别人的反馈、资源限制和不同方案改变自己的判断；AI 的建议也可以被拒绝。
- **Act：** 做出一个可以测试的版本，说明它有用在哪里，还有哪里不行。

## 现在，我们走到哪了

我们还在准备首届活动。这本手册记录的是正在形成的安排，不是假装已经发生过的成功故事。

第一步是拟举办 **PRISMS House Game 校内个人预选赛**，日期待定，安排在主活动之前。PRISMS 学生个人参赛，报名前公布评分标准，据此选出或组成 **两支 PRISMS 代表队**。预选赛也负责试跑技术、评审和现场流程。

第二步是拟于 **2027 年 4 月 17 日，星期六**，在 PRISMS 举行的一日主黑客松，面向 **30–60 名 PRISMS 及受邀的周边初、高中学生**，每队 **2–5 人**。日期、场地、校外参与、监督及财务路径仍需校方确认。获批前，我们会继续准备，但不会把待定写成已确定。

## 未来不是先把人数写大

我们当然想让更多人有机会来。但在那之前，我们更想知道：第一次参加的人有没有找到能做的事？团队有没有因为反馈修改过方向？散场一个月后，还有没有人愿意打开那个项目？

如果这些没有做好，再多一张大合照也不会自动补上。

所以，下一步先是一场能认真复盘的活动，再是有人愿意回来的小聚会，再是下一批同学可以接得住的组织。跨校合作、更长时间的项目支持，都可以谈，但要等到有人、有时间、有实际需求时再往前走。[规划的具体步骤在这里。](docs/zh/roadmap.md)
