# REFR/ACT 执行手册

[中文首页](../../README.zh.md) / [English](../en/operations.md)

这份手册写的是本届准备怎么做，不是往届战报。[线下排期](schedule.md)是对外日程的统一入口；这里记录负责人、验收方式和备用安排。场地、容量、报名细则和时间没有确认前，不写进对外承诺。

## 1. 活动边界

DAY 1 布展与联调，DAY 2–DAY 5 为线下正赛。面向所有创作者开放报名，不以学生身份、学校或专业作限制。团队自己选题，现场提交可演示的原型和简短的过程说明。企业题、产品试用和面谈均为自愿。

开报名以前先确认：场地与容量、各区开放时段、团队人数规则、无障碍与安全安排、报名和取消方式、奖项与评审流程。合作方不能先替组织者承诺这些安排。

## 2. 谁来负责

| 工作 | 必须交付 |
| --- | --- |
| 总协调 | 倒排总表、决策记录、风险清单和对外口径。 |
| 场地与安全 | 工位和各区平面图、位置与容量核验、应急联系人。 |
| 参赛者与导师 | 行前指南、组队流程、导师值班与求助方式。 |
| 评审与作品展 | 提交清单、评委说明、回避规则、展桌号及决赛名单。 |
| 技术与物料 | 普通参赛设备的联网与提交实测，备用收件、设备借还台账。 |
| 合作与财务 | 确认单、到场联系人、物资发放记录、专项奖与赞助权益单列、赛后回执。 |

每项交付指定一名负责人和一个备份。会上留下做什么、谁接、哪天验收，避免所有人都知道问题却没人接手。

## 3. 倒排时间线

| 节点 | 完成标志 |
| --- | --- |
| 报名开放前 | 日期、场地、容量、现场监管与财务确认；公告包含报名条件、组队规则和基本日程。 |
| 合作定稿前 | 技术支持、发放数量、使用限制和回执口径写入确认单；企业命题有一页题目说明。 |
| 开赛前一周 | 走查网络与供电；测试报名、签到、提交和计分；发布参赛指南，确认联系人、展桌和备份。 |
| 赛后 | 按确认单交付回执；归还设备，对账，处理授权，并记录下一次要改什么。 |

## 4. 正式开赛前的试跑

用一台普通参赛设备走一遍入场、联网、拿样例、提交和现场演示。让不熟悉流程的人照指南操作，记录卡点及修复人。必要时安排短时演练；演练不等同于主活动，也不产生晋级席位。

## 5. 场地、人员与安全

- 确认开发区、技术桌、作品展、舞台、面谈区、休息区和通道的位置。面谈区与评审动线分开。
- 先查容量、供电、无障碍路线、饮食过敏信息、设备操作条件和现场应急联系人。未成年人参与按活动正式公布的授权和现场监管规则执行。
- 活动时段、场地和安全安排由负责人员确认。提供助理或导师的人不能代替现场安全监管。

## 6. 预算与合作伙伴

分开记制作、场地、餐饮、硬件与耗材、宣传物料及奖项。列数量、用途、支付方式和负责人；没有书面确认的合作不计入可用预算。

品牌露出、设备与工具、技术桌、产品试用和联合工作坊的交付分别写进确认单。企业可以单独出题，由双方先定验证范围和交付；如果设置专项奖，由命题企业另行出资、单独记账，不改变正赛评分。[企业与社区合作](partnerships.md)介绍了不同合作方式。

## 7. 报名与参与者沟通

正式报名页要写清谁能参加、需要提交什么、如何组队、何时收到确认，以及未成年参与、饮食和无障碍方面的安排。只收办活动需要的信息，报名名单不向合作方提供。

赛前确认邮件、行前指南及现场提醒都链接到同一版日程与规则。组队靠意愿，不强制选择企业题或赞助工具。

## 8. 技术与物资

- 用普通参赛设备测试网络、登录、权限、工具额度及提交回执，留一条离线或备用收件路径。
- 测投影、音频、计时屏和转接头；整理供电、借还登记及硬件工作区安全。
- 工具优先提供能直接运行的样例。确认额度的适用地区、资格、有效期、并发及数据规则。
- 每次测试留设备、步骤、结果、卡点与修复人。

## 9. 提交与评审

团队可做软件、硬件、游戏或交互等原型。提交内容包括项目说明、可演示的核心流程、团队做过的主要取舍以及能说明成败的测试记录。不要把曾经成功一次说成可上线。

**DAY 4 展评，DAY 5 决赛。** 按桌号安排初评，每队获得同等的演示机会。赛前定稿提交要求、评委回避、评分项、同分与迟交处理；所有评委使用同一版规则。决赛另作演示与问答。企业出题、提供工具、赞助或接触候选人，都不提供评审优待。

## 10. 活动当天怎么运行

| 日程 | 筹备组要核对的事项 |
| --- | --- |
| DAY 1 · 布展 | 同时走一遍设备、网络、提交和备用通道，核对技术桌、合作方与展位位置。 |
| DAY 2 · 开幕 | 签到、发规则与求助方式，协助未组队的人找到想一起做事的同伴。 |
| DAY 3 · 开发 | 导师巡场，安排可选工作坊与技术桌，保留连续制作时间。 |
| DAY 4 · 展评 | 提前提醒提交截止，按桌号安排作品展和初评；独立面谈区按预约表运行。 |
| DAY 5 · 决赛 | 按公布顺序路演和问答，记录奖项、设备归还和结束安排。 |

现场运行表只保留时间、动作、负责人、备用人和状态。若规则或时段临时调整，统一通知所有受影响的团队。

## 11. 出了问题怎么办

| 情况 | 处理方式 |
| --- | --- |
| 网络或工具不可用 | 开备用网络或离线路径，记录影响范围；如确需延时，统一通知。 |
| 提交入口故障 | 用预先宣布的备用通道收件并记录时间，所有队伍适用同一规则。 |
| 导师、评委缺席 | 按候补顺序补位，检查回避关系与所有队伍的演示时长。 |
| 身体不适或现场安全问题 | 联系场地与活动安排中的应急负责人，现场先保障人员安全。 |
| 资源未到或预算变化 | 停止未确认的采购或承诺，联系相应伙伴，改用确认过的备用资源。 |

## 12. 收尾与复盘

核对设备归还、奖项发放与赞助履约。赛后回执把做过的事说清楚：链接与截图、可验证的数据、资源发放和匿名反馈。企业命题按约交原型说明和验证记录；没有授权的素材和个人资料不公开。

复盘时记录一次具体的卡点和解决办法。下次谁负责、什么时候完成，也写下来。
